# 发布前检查清单 + 交付节奏

## 六条自查（Cyan 2026-07-23 定稿）

每次做完一套知识卡片，交付前逐条自查：

- ✅ 标题 Hook（够不够让人好奇、想点进来）
- ✅ 标题字号达到合理范围内的最大字号（不是随便塞得下就行）
- ✅ 第一张封面有 3 秒吸引力（封面这一屏要能独立成立）
- ✅ 8-10 张图视觉统一，排版舒适合理
- ✅ 正文字号、标注字号手机端可读（对照 `typography-rules.md` 的下限表）
- ✅ 最后一页要带品牌 Slogan（印在卡片图片本身里，不是只写在配文文字里）

## 草稿 vs 定稿交付节奏

- **迭代阶段**（换标题、换图、调字号，还在来回改）：每轮只生成并发送 `contact.png` 预览小图，**不要打包 zip**——打包这个动作本身也会消耗不必要的时间/资源，迭代阶段完全没必要。
- **定稿阶段**：只有用户明确说"定稿了/OK了/可以导出了"之后，才 `zip` 打包高清图并发送。
- 如果不确定是不是定稿，直接问"这版定了吗，需要我打包高清图吗"，不要默认每轮都打包。

## 公众号配文

- 配文标题**不能直接照抄卡片封面的大标题**，两者要各自独立起一个 hook 够强的标题，换不同角度（比如封面用"事件反差"，配文换"人物性格反差"或"数字反差"）。
- 配文结尾固定结构：一句互动引导问题 + 关注引导语（含品牌 slogan）+ hashtag。

## 渲染环境提示

新容器/新会话如果发现 `render.mjs` 里 `createRequire('/home/node/.claude/skills/guizang-social-card-skill/')` 这条路径找不到模块，说明渲染 skill 没装——直接在项目目录 `npm install playwright --no-save --no-audit --no-fund`，然后把 `render.mjs` 开头两行改成 `import { chromium } from 'playwright';` 即可，不影响其余渲染逻辑。
